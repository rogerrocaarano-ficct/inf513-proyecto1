# UC-001 Gestión de usuarios

## Objetivo

Cada participante del trámite de titulación tiene una cuenta de usuario con un rol, para usar el sistema. Quien administra las cuentas las crea, las modifica, las desactiva o reactiva y las lista, y cada usuario mantiene sus propios datos de contacto.

## Actores

| Actor | Participación |
| --- | --- |
| Administrador | Principal: gestiona las cuentas de todos los roles; es el único que gestiona las cuentas de director de carrera y de administrador (FR-053) |
| Director de carrera | Principal: gestiona las cuentas de docente, docente de Taller de Grado, secretario(a) de dirección de carrera y estudiante (FR-050) |
| Secretario(a) de dirección de carrera | Principal: crea, modifica y lista las cuentas de estudiante (FR-051) |
| Usuario | Cualquier usuario: modifica sus propios datos de contacto y su foto de perfil (A4, A5). Recibe los avisos sobre su cuenta |

## Precondiciones

- Quien hace la solicitud tiene una cuenta de usuario activa.
- La primera cuenta de administrador existe desde la instalación del sistema.

## Flujo básico: crear una cuenta

1. El administrador, el director de carrera o el secretario(a) pide crear una cuenta con el nombre completo, la dirección de correo y el rol; para un estudiante indica además su registro universitario, su cédula de identidad y su teléfono (FR-026).
2. El sistema comprueba que el rol de quien lo pide le permite crear cuentas del rol pedido (FR-050, FR-051, FR-053).
3. El sistema valida los datos y comprueba que la dirección de correo y el registro universitario no pertenecen a otra cuenta (FR-033).
4. El sistema crea la cuenta, activa y con un solo rol (FR-036).
5. El sistema confirma la creación a quien la pidió y avisa a la nueva cuenta, en su dirección de correo, que tiene una cuenta con ese rol (FR-035).

## Flujos alternativos

### A1. Modificar una cuenta

1. Quien administra la cuenta pide modificar sus datos o su rol (FR-031).
2. El sistema comprueba que el rol de quien lo pide le permite gestionar la cuenta, y también el rol nuevo si lo cambia (FR-050, FR-051, FR-053).
3. El sistema valida los datos, como en el flujo básico, pasos 3 y 4.
4. Si la cuenta pierde un rol y participa en trámites en curso, el sistema lo advierte a quien hizo el cambio (FR-034).
5. El sistema registra el cambio, lo confirma a quien lo pidió y avisa al usuario de la cuenta (FR-035).

### A2. Desactivar o reactivar una cuenta

1. El administrador o el director de carrera pide desactivar o reactivar una cuenta (FR-032).
2. El sistema comprueba que el rol de quien lo pide le permite cambiar el estado de las cuentas de ese rol (FR-050, FR-053).
3. El sistema cambia el estado de la cuenta. Una cuenta desactivada no puede usar el sistema y conserva sus datos y su historial (FR-032).
4. Al desactivar, si la cuenta participa en trámites en curso, el sistema lo advierte a quien hizo el cambio (FR-034).
5. El sistema confirma el cambio a quien lo pidió y avisa al usuario de la cuenta, con el nombre de quien hizo el cambio (FR-035).

### A3. Listar las cuentas de un rol

1. Quien administra las cuentas pide la lista de las cuentas de un rol (FR-030).
2. El sistema comprueba que el rol de quien lo pide le permite gestionar las cuentas de ese rol.
3. El sistema responde solo a quien lo pidió, con los datos de cada cuenta y su estado, incluidas las desactivadas. Listar no cambia ninguna cuenta ni avisa a nadie.

### A4. Modificar los datos de contacto propios

1. El usuario pide cambiar la dirección de correo o el teléfono de su propia cuenta (FR-049).
2. El sistema valida los datos y comprueba que la dirección de correo nueva no pertenece a otra cuenta (FR-033).
3. El sistema registra el cambio y avisa al usuario (FR-035).

### A5. Cargar o cambiar la foto de perfil

1. El usuario envía una imagen como foto de perfil de su propia cuenta (FR-037).
2. El sistema comprueba que la imagen es PNG o JPG y no supera el tamaño máximo (NFR-006).
3. El sistema guarda la foto en la cuenta y avisa al usuario (FR-035).

## Excepciones

En todos los casos el sistema informa el motivo a quien hizo la solicitud y no registra nada.

| ID | Dónde | Situación |
| --- | --- | --- |
| E1 | Todos | Quien hace la solicitud no tiene una cuenta, su cuenta está desactivada, o su rol no le permite hacerla |
| E2 | Flujo básico, A1, A4, A5 | Falta un dato obligatorio o algún dato no tiene el formato correcto; el sistema indica cada dato inválido (NFR-001) |
| E3 | Flujo básico, A1, A4 | La dirección de correo o el registro universitario ya pertenecen a otra cuenta (FR-033) |
| E4 | A1, A2 | La cuenta indicada no existe |
| E5 | A1, A2 | Se desactiva, o pierde el rol de administrador, la única cuenta de administrador activa (FR-038) |
| E6 | A1, A2 | Quien lo pide intenta cambiar el rol de su propia cuenta o desactivarla |
| E7 | A2 | La cuenta ya está en el estado pedido |
| E8 | A1 | El rol nuevo es el que la cuenta ya tiene |

## Postcondiciones

- Flujo básico: la cuenta existe, activa, con un solo rol, y su usuario recibió el aviso.
- A1, A2: la cuenta tiene sus datos, su rol o su estado nuevos, y el usuario recibió el aviso. Los trámites en curso en que participa no cambian.
- A3: nada cambia.
- A4, A5: la cuenta del usuario tiene sus datos de contacto o su foto nuevos, y el usuario recibió el aviso.

## Reglas de negocio

- Cada cuenta tiene un solo rol: estudiante, docente, docente de Taller de Grado, secretario(a) de dirección de carrera, director de carrera o administrador (FR-036). Quien administra y además participa en un trámite usa dos cuentas distintas.
- El administrador gestiona las cuentas de todos los roles; el director de carrera, las de docente, docente de Taller de Grado, secretario(a) y estudiante; el secretario(a) crea, modifica y lista las de estudiante, pero no las desactiva ni reactiva (FR-050, FR-051, FR-053).
- Nadie cambia el rol de su propia cuenta ni la desactiva.
- El estudiante debe tener registro universitario, cédula de identidad y teléfono; para los demás roles son opcionales (FR-026).
- Ninguna dirección de correo ni registro universitario se repite entre cuentas (FR-033).
- Siempre hay al menos una cuenta de administrador activa (FR-038).
- Todo cambio en una cuenta se avisa al usuario de esa cuenta (FR-035).
- Una cuenta no se borra: se desactiva y conserva su historial (FR-032).
- El usuario se identifica por la dirección de correo desde la que envía sus solicitudes.
- Ser tutor o miembro del tribunal no es un rol de la cuenta: sale de las designaciones de cada trámite (UC-003).
- El registro de cambios de las cuentas se consulta en UC-007 (FR-052).
